# Slantsmith

Free, offline, light word tool for songwriters: perfect, slant and multi-syllable rhymes from our own word model, a grammar checker with a lyric mode, a lyric editor, and Mix help (loudness, EQ, checklists). Solo developer, $0 budget, part-time (~10 h/week).

Read first: `PRODUCT.md` (users, purpose, principles), `DESIGN.md` (visual rules, tokens), `docs/requirements.md` (the 20 v1.0 requirements with acceptance tests), `docs/decisions.md` (ADRs, licences), `docs/session-summary.md` (how we got here).

## Stack

- Angular (latest stable, standalone components, signals) as an installable offline PWA (`@angular/service-worker`). Not Flutter (ADR-01).
- Rhyme and grammar engines run in a Web Worker (ADR-04). Engine code is plain TypeScript in `src/engines/`, erasable syntax only (no enums, no parameter properties) so Node runs it directly.
- Storage: IndexedDB. One record per song; versions ("takes") in a separate store (ADR-07).
- Hosting: static, free subdomain (decided at deploy time). No backend, no analytics, lyrics never leave the device.

## Commands

```bash
pip install wordfreq      # only to rebuild the model
npm run build:model       # tools/build_word_model.py -> src/assets/model/en-us/
npm test                  # node --test on test/*.test.ts (rhyme set, speed, explicit filter, dropped-g)
```

## Layout

- `tools/build_word_model.py`, `tools/data/` (CMU dict, misspelling/slur blocklists, explicit list)
- `src/assets/model/en-us/` generated: lexicon.txt, phones.bin (1 length byte + 1 byte per sound: low 6 bits sound id, high 2 bits stress), meta.bin (bit 4 = explicit, bit 5 = function word, bits 0-3 = noun/verb/adjective/adverb bitmask), commonness.bin (zipf*32), manifest.json
- `src/engines/model.ts` (decode: `wordTypes()`, `isFunctionWord()`), `src/engines/rhyme.ts` (RhymeEngine: rhymes(), phrase())
- `tools/data/wordnet/` Open English WordNet LMF XML, fetched on demand by `build_word_model.py` (gitignored, like wordfreq's own data; not shipped)
- `test/` rhyme and grammar test sets (CSV) + tests
- `design/screens/` the approved phone screens as HTML artboards (Design canvas format; open in a browser for reference, do not ship). `design/screens/canvas.json` lists them.
- Grammar rule data for Sprint 4 is ready in `tools/data/`: lyric_allowlist.txt, doubled_word_rule.json.
- `src/app/settings/` SettingsService (signals, localStorage-persisted) + `/settings` route, built from the approved `Settings.dc.html` artboard.
- `src/app/songs/` SongStorageService (IndexedDB, ADR-07) + Songs list (`/songs`), lyric editor (`/songs/:id`), and Takes (`/songs/:id/takes`) routes, built from `Songs.dc.html`/`SongsEmpty.dc.html`/`Main.dc.html`/`Takes.dc.html`.
- `src/app/shell/tab-nav.component.ts` the shared bottom tab bar (Songs/Rhymes/Settings), used by all three screens.

## Conventions

- Smallest change that fully works; no dependencies for a few lines; a test for every non-trivial branch.
- A known-limited shortcut gets a comment: `shortcut: <limit>, <when to upgrade>`.
- Follow DESIGN.md: studio dark default, one lamp card per screen, ruby #A71D31 only for record-light moments (tapped word, saved dot, primary buttons), rhyme families = letter + underline style, 44 px targets, Manrope self-hosted.
- US English only in v1.0. Explicit words shown by default (filter in Settings); slurs removed at build.

Two follow-up fixes the same day (2026-11-04), reported after trying it: first, a real bug — the trigger was a single `click`, which also fires on every normal click-to-place-the-caret, so after tapping any word once you could no longer click back into the textarea to keep typing without reopening the sheet. Changed the trigger to `dblclick` (double-click/double-tap); a single click is a plain caret placement again. Second, a desktop design gap — the forced-overlay sheet was still the narrow 480px bottom-sheet card, just floating centred-ish in a big window, not actually styled for desktop. `DESIGN.md`'s "Responsive" section now specs, and `rhyme-sheet.component.css` now builds, a `:host(.overlay)` desktop treatment: a centred 640px modal dialog (rounded all four corners, no drag grabber) instead of the sheet shape — Rhymes' own permanent-panel usage is untouched since it never sets `.overlay`.

A third bug turned up immediately after, from a screenshot: on "Slant" (50 results, taller than "Perfect"'s 14), the filter-chip rows visibly overlapped the first couple of word rows. First guess (the new modal's `transform: translate(-50%,-50%)` colliding with `.rows`' own scrolling, a known Chromium paint quirk) was wrong and got fixed anyway (re-centred with flexbox instead, since that's the more correct way regardless) — but the overlap was still there after that fix, which is what proved the real cause: `.sheet`'s `display: flex; flex-direction: column` had no `flex-shrink: 0` on anything except `.rows`, so whenever total content exceeded the sheet's height (bottom sheet, desktop panel, or the new modal's `max-height` alike), flexbox's default shrink-everything behaviour compressed the header/tabs/filters/footer too — their fixed-size buttons then overflowed their shrunk boxes and visually overlapped the list below. This was a latent bug in the original Sprint 2 rhyme sheet, not something the modal introduced; it just hadn't been forced to shrink before (the mobile sheet and Rhymes' panel both had enough natural room). Fixed with one rule, `.sheet > *:not(.rows) { flex-shrink: 0; }`, verified clean on all three surfaces (the new desktop modal, the mobile bottom sheet, and the Rhymes page's desktop panel).

A fourth bug, introduced by that same re-centring-with-flexbox change: setting `.sheet { position: static }` for the desktop modal case made `.scrim` (`position: absolute`, drawn first in the DOM) paint *above* it instead of behind it — absolutely-positioned elements always stack above static ones regardless of DOM order. The scrim's dark tint washed out every colour in the dialog, and since it was also on top, it ate every click (reported as "the dialog is darken and can't click"). Fixed by giving `.sheet` `position: relative` instead of `static` in that case — same flex-item layout, but now a positioned element, so normal DOM-order stacking (later wins) puts it above the scrim again. Verified: colours back to normal, and clicking "Use" actually replaces the word and closes the sheet.
